# OpenMinis parity matrix

This is the live accounting of the official OpenMinis repository against the
client-server refactor. It is deliberately explicit: **the project is not at
100% parity yet.** Two generated inventories make every file visible:

- [`android-code-inventory.csv`](android-code-inventory.csv) — every Android
  source/asset file with an owner and parity status.
- [`repo-code-inventory.csv`](repo-code-inventory.csv) — every file in the
  official repository, including iOS, bundled dependencies, scripts and docs,
  with a `scope` column.

Both are generated by `scripts/android_inventory.py`; run it after pulling a new
OpenMinis revision:

```sh
python3 scripts/android_inventory.py --source /path/to/OpenMinis/src/android \
  --out docs/android-code-inventory.csv
python3 scripts/android_inventory.py --mode repo --source /path/to/OpenMinis \
  --out docs/repo-code-inventory.csv
```

## Status legend

| Status | Meaning |
|---|---|
| `implemented` | Runs fully server-side or the bridge is complete and verified. |
| `partial` | Some behaviour exists on the server, but parity is not complete. |
| `device-only` | Inherently requires the phone (sensors, WebView, notifications, OAuth consent, APK install). |
| `ui-only` | Presentation; remains in the APK. |
| `local-fallback` | Kept for offline/local mode. The paired server is the default execution path. |
| `replaced-by-server-container` | Legacy PRoot/rootfs assets; no longer used by the agent. |
| `reference` | iOS source, kept for behavioural comparison. |
| `not-applicable` | Tests, debug tooling, dependencies, docs or build files. |
| `unclassified` | Must be zero. Currently zero. |

## Blocking parity gaps (ordered)

1. **Provider parity.** OAuth token custody/refresh (Claude, Copilot, Gemini,
   Kimi, xAI, OpenRouter, Antigravity), OpenAI Responses API, per-model thinking
   rules/budgets, Anthropic prompt caching and thinking-block preservation,
   Gemini thought signatures, model catalogs and quota adapters. Native
   Anthropic/Gemini auxiliary calls are now translated.
2. **Server data stores.** Memory, skills and MCP configuration are still owned
   by the app; the server receives fragments. Moving the stores would let
   server-originated headless runs use memory/skills/MCP and remove the
   structured-fragment bridge.
3. **Agent-loop edge semantics.** Mid-run steering/queued-prompt injection, SSE
   run replay/reconnect, interrupted-tail repair, user-ask recovery across
   process death, subagent budgets/closing nudges, and concurrent tool dispatch.
4. **Config write confirmation.** `minis-config get` is server-backed.
   `minis-config set` returns `CONFIRMATION_REQUIRED` because the app's
   confirmation sheet is not yet reachable from a server-originated CLI call.
5. **File browser write UI.** The server API supports list/read/upload/delete/
   rename/mkdir and the browser deletes server files. The File-backed browser
   is still a one-way workspace cache, so upload/rename UI actions and
   `@file` previews need a direct remote adapter.
6. **Backup/restore.** `.minisbak` format, crypto, merge and rclone transport
   remain in the app; server sessions/workspaces are not included.
7. **Server/client data parity.** Session folders/groups, usage/quota
   aggregation, config audit and model catalogs remain client-side.
8. **Accounting depth.** Every Android file has an owner/status, but `partial`
   rows are not yet individually linked to a server implementation and test.
   The iOS tree is accounted for as reference, not implemented.

## Verified so far

- Dedicated Debian 12 full-distro container: root shell, apt, Node, Python,
  build tools; isolated from host and other Docker networks.
- Server shell/file tools execute in that container through an authenticated
  private API.
- Real OpenRouter run with the server-owned prompt returned Debian
  `uname`/`os-release`, and the model saw the injected skills fragment.
- Server prompt context (`prompt_context`) replaces the app-built prompt for
  server runs; the old PRoot/Alpine identity text is rewritten to Debian.
- Same-model retry and model fallback verified with a failing upstream.
- Client tool round-trip (`await_client` → POST result → same SSE continues),
  including a device CLI shell command (`android-device info`).
- Server PTY terminal verified through Caddy and the server proxy: Debian bash
  prompt, command echo and real command output.
- Server file API verified end-to-end: list, upload, raw download, delete,
  rename, mkdir, and workspace removal on session delete.
- Sandbox CLI tools verified: `minis-sessions-cli list/messages`,
  `minis-config get`, `minis-model-use list/run`, `minis-scheduled list`.
- Real `minis-model-use run` returned a live model response.
- Auxiliary `/v1/chat/completions` translation verified against a native
  Anthropic SSE upstream (streaming and non-streaming).
- Request image budget and compaction/offload unit-tested.
- Android 1.16.6 build 44 is the current source release; 1.16.5 build 43 is
  published with the terminal and server fallbacks.
