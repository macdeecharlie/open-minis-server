# OpenMinis parity matrix

This is the live accounting of the Android codebase against the client-server
refactor. It is deliberately explicit: **the project is not at 100% parity
yet.** The file-level inventory is in
[`android-code-inventory.csv`](android-code-inventory.csv) and is generated by
`scripts/android_inventory.py` so no source file can disappear from the matrix
without a diff.

Inventory snapshot: **2,183 files / 864,662 lines** under `src/android`
(1,501 Kotlin files / 404,933 lines). The Android tree includes tests,
resources, generated schemas, and the bundled runtime assets.

## Status legend

| Status | Meaning |
|---|---|
| `implemented` | Runs fully server-side or the bridge is complete and verified. |
| `partial` | Some code/behavior exists on the server, but parity is not complete. |
| `device-only` | Inherently requires the phone (sensors, WebView, notifications, OAuth consent, APK install). |
| `ui-only` | Presentation; remains in the APK. |
| `replaced-by-server-container` | Legacy on-device sandbox code/assets kept for reference/fallback; the agent now uses the Debian container. |
| `pending-remote-pty` | Superseded for server mode: the terminal now uses the Debian sandbox PTY. Local PTY remains the offline fallback. |
| `unclassified` | Must be zero. Currently zero. |

## Blocking parity gaps (ordered)

1. **Server-owned prompt and context pipeline.** Move SOUL, tool bullets,
   skills/MCP/memory fragments, persona reminders, token estimation,
   offload/compaction, warm-up trim and orphan-tool repair to the server.
2. **Provider parity.** Native Gemini, OAuth custody/refresh, model groups and
   fallback, per-model thinking rules, image budget, provider-specific retries
   and error classification, quotas.
3. **Agent-loop parity.** Auto-retry, fallback chain, empty-turn recovery,
   tool-loop detector, steering/queued prompts, subagent execution and
   completion, user-ask recovery, interrupted-tail repair.
4. **Scheduled tasks on the server.** Persistence, interval/calendar/once,
   targets, headless execution and run history are live. Still pending:
   app-side task sync, prefills/completion triggers, and completion
   notifications when the app is closed.
5. **Remote GUI surfaces.** File browser/preview and the interactive terminal
   now use the server: the file browser mirrors the session workspace into the
   existing File-backed UI, and the terminal uses a real PTY in the Debian
   sandbox. `@file` mentions and attachment uploads still need the server
   adapter; chat tool cards already show server output.
6. **Skills, memory and MCP data.** Server-side skill/memory stores and
   on-demand MCP tooling; attachments and device-local files must be uploaded
   or bridged deliberately.
7. **Backup/restore parity.** Move the `.minisbak` format, merge and crypto to
   the server; keep rclone transport/device UI as appropriate.
8. **Device CLI bridge.** Continue the `await_client` pattern for every
   `android-*` shell CLI, or provide equivalent typed tools. A server shell
   cannot run them directly.

## Verified so far

- Dedicated Debian 12 full-distro container with root shell, apt, Node, Python
  and common build tools; isolated from host/other Docker networks.
- Server file API verified end-to-end through the sandbox container:
  list, upload, raw download, and persisted workspace.
- Server PTY terminal verified through Caddy and the server proxy: Debian bash
  prompt, command echo and real command output.
- Server-side shell/file tools execute in that container via an authenticated
  private API.
- Real OpenRouter model run with server shell tool returned Debian
  `uname`/`os-release` output.
- Client tool round-trip (`await_client` → POST result → same SSE continues).
- Session persistence, private release feed, authenticated APK download.
- Android 1.16.2 build 40 signed with the stable sideload key; embedded token
  authenticates against the live server.
